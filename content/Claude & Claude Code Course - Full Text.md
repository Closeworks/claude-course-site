## 3. How Claude Actually Thinks

[IMAGE: Diagram showing Claude's context window and thinking process]

Understanding how Claude works under the hood will instantly make you better at using it.

You don't need to be technical. Just understand three concepts.

### 🧠 Concept 1: The Context Window

Think of this as Claude's short-term memory.

Everything you type — and everything Claude responds with — fills up this memory. Claude can hold about **200,000 tokens** at once. That's roughly 150,000 words. An entire novel. An entire codebase.

This means you can paste massive documents, long instructions, and complex multi-part requests — Claude processes ALL of it.

Most people underuse this. They ask one-line questions. That's like hiring a consultant and only giving them 30 seconds of context.

**Give Claude more. Get more back.**

### 🛡️ Concept 2: Constitutional AI

Claude isn't just trained on human feedback. It has a set of principles — like a constitution — that guide its behavior.

What this means for you:
- Claude is more honest than other models
- It pushes back on bad ideas (this is a feature, not a bug)
- It says "I'm not sure" instead of making things up
- It's designed to be helpful without being harmful

### 💭 Concept 3: Extended Thinking

Claude has a "deep work" mode. Instead of firing off the first thing that comes to mind, it pauses to reason step by step.

You trigger it naturally:
- *"Think carefully about this..."*
- *"Consider all the tradeoffs..."*
- *"Step by step, work through..."*

The difference between a quick answer and a thought-through answer is massive — especially for strategy, code architecture, and complex decisions.

## 4. Git — Your Safety Net

[IMAGE: Git workflow diagram]

Before we go deeper, you need a safety net.

**Git is an unlimited undo button for your entire project.**

Every time you save a snapshot (called a "commit"), you can always go back to that exact state. This means you can let Claude go wild — if it breaks something, you just rewind.

### The 7 Commands You Need

```
git init              → Start tracking a project
git status            → See what changed
git add .             → Stage all changes
git commit -m "msg"   → Save a snapshot
git log               → See your history
git diff              → See exactly what changed
git checkout -- .     → UNDO all uncommitted changes
```

That last one is your panic button. If Claude makes a mess, `git checkout -- .` takes you back to your last commit.

### The Workflow

1. Tell Claude to build something
2. Review what it created
3. **Like it?** → `git add .` then `git commit -m "Added feature X"`
4. **Don't like it?** → `git checkout -- .` to undo everything
5. Repeat

### 💡 Pro Tip

Claude Code understands Git natively. You can say:

- *"Commit everything with the message 'initial setup'"*
- *"Show me what changed since the last commit"*
- *"Undo the last change you made"*

You don't even need to type the commands yourself.

## 1. Prompting Claude Like a Pro

[IMAGE: The C.R.A.F.T. prompting framework diagram]

The quality of Claude's output is directly tied to the quality of your input.

Most people give Claude vague instructions and wonder why the output is generic.

This is like hiring a world-class consultant and saying *"help me with business stuff."*

Here's the framework that fixes this.

### 🎯 The C.R.A.F.T. Framework

**C — Context.** Give Claude the background.
```
Bad:  "Write me an email."
Good: "I run an AI automation agency targeting real estate companies.
       I need a cold outreach email to a brokerage owner."
```

**R — Role.** Tell Claude who to be.
```
Bad:  "Help me with marketing."
Good: "Act as a senior growth marketer who specializes in B2B SaaS."
```

**A — Action.** Be specific about the output.
```
Bad:  "Make this better."
Good: "Rewrite this headline to be more benefit-driven.
       Give me 5 variations under 10 words each."
```

**F — Format.** Specify how you want it delivered.
```
Bad:  "Give me ideas."
Good: "Give me 10 ideas in a numbered list. Each with a one-line
       description and difficulty rating (easy/medium/hard)."
```

**T — Tone.** Set the voice.
```
Bad:  "Write a post."
Good: "Write an Instagram caption. Conversational, slightly edgy.
       No corporate speak. Sound like a real person."
```

### 🧪 Advanced Moves

**Chain prompting** — Break complex tasks into steps:
*"First analyze my competitor's landing page. Then identify 3 weaknesses. Then rewrite my page to exploit those gaps."*

**Few-shot examples** — Show Claude what good looks like:
*"Here are 3 headlines I love: [examples]. Write 5 more in this exact style."*

**Constraints** — Set hard boundaries:
*"Under 100 words. No jargon. 8th grade reading level. Must include a CTA."*

These techniques compound. Use them together and Claude's output goes from "pretty good" to "did a human write this?"
